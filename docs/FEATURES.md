# 功能设计（v2，2026-10-27）

## 设计原则
1. 产品只服务一条主线：**意图 → 理解 → 在手机上执行 → 风险把关 → 交付结果**。
2. **dsh 已经有的不重复造**：子 agent、技能、MCP、上下文压缩、网页搜索（web-search-deepseek）、定时任务、browser-use 的 provider 机制，都直接复用。
3. 只有**安卓独有的东西**才由 App 来做：感知、执行、触发、入口、把关。
4. 每加一个功能都要过这一关：它是不是让“交给手机 agent 去办”变得更**可能**、更**省事**、更**放心**？三条都不沾就不做。

## 功能地图
图例：✅ 保留（来自 Pure）｜🆕 新增（Pure 没有）｜♻️ 用 dsh 原生能力替代｜❌ 砍掉

### A. 感知：agent 能看到什么
- ✅ 读屏：无障碍界面树为主，截图为辅（模型支持图片输入）
- 🆕 **助手 API 上下文**：把本 App 设为系统默认数字助手。用户唤起时，系统会在用户同意的前提下把当前屏幕的结构和截图交给 agent，**不需要开无障碍就能回答“这个页面上…”这类问题**
- ✅ 通知读取（按 App 设白名单，默认为空）
- ✅ 设备状态：电量、网络、位置、传感器、存储空间
- ✅ 联系人、短信、通话记录、日历（敏感级，默认关闭）
- ✅ 文件内容：文本、PDF、图片，配合 rg 做全盘搜索

### B. 执行：agent 能做什么
- ✅ 文件：查找、读取、新建、修改、复制、移动、重命名、删除、压缩和解压（包括 SD 卡）
- ✅ App：列出应用、打开应用、通过深链或 Intent 跳转到指定页面、分享
- ✅ 屏幕操作：点按、滑动、滚动、输入、返回、全局手势
- ✅ 系统开关：亮度、音量、勿扰、Wi-Fi、蓝牙、闹钟（受权限限制的部分走 Shizuku）
- ✅ 消息：发短信，以及通过 Intent 预填好内容再由用户点发送（危险级，每次都要审批）
- ✅ 媒体控制：通过媒体会话控制正在播放的音乐和视频（暂停、下一首、音量）。❌ 不做内置播放器
- ✅ Shizuku 增强（可选）：更可靠的输入注入、授予权限、改系统设置、静默安装
- ♻️ 浏览器：把 App 内的 WebView 注册成 dsh 的 browser-use provider（借鉴 Pure 的“操作轨迹 + 停止按钮”）
- ♻️ 网页搜索和抓取：dsh 自带的 web_search（DeepSeek）和 web_fetch，并阻断访问内网地址
- 🆕 **agent 独立屏幕（可选，需要 Shizuku）**：agent 在一块虚拟屏上操作 App，不占用你正在用的屏幕（借鉴 DSHA 和 Rungic）

### C. 持续：没人在场时也能干活
- ✅ 定时任务：“每周一早上 8 点…”。♻️ 执行引擎用 dsh 的 schedule，用 AlarmManager 唤醒
- ✅ **条件触发**：连上或断开 Wi-Fi、蓝牙、插拔耳机、充电、地理围栏、某个 App 被打开、收到通知、屏幕亮灭、时间点；附加条件包括电量、日出日落、星期几。这一层由 App 负责（只有安卓才能监听这些事件），触发后交给 dsh 执行
- ✅ “固化动作”：触发后直接执行预先定好的步骤，不经过模型，不消耗 token
- ✅ 对外的 Intent 接口：Tasker、MacroDroid 等工具可以把任务交给 agent
- ✅ 结果通知：点开通知直接跳到对应的会话

### D. 扩展
- ♻️ 技能（Markdown 剧本）：dsh 原生支持
- ♻️ MCP：dsh 原生支持；新增或修改 MCP 配置都要审批
- ♻️ 子 agent、上下文压缩：dsh 原生能力，由 agent 自己调度。❌ 不做配置界面
- ❌ 个人记忆（用户决定砍掉；用户可以自己往 dsh 原生的说明文件里写内容，零成本）

### E. 交互入口
- 🆕 **系统助手入口**：长按电源键或手势唤起（VoiceInteractionService），这是阻力最小的入口
- 🆕 快捷设置磁贴、桌面小部件（显示最近任务）
- 🆕 分享菜单：“用 agent 处理这个文件或链接”
- ✅ 对话界面：流式显示步骤；可以点开工具调用查看详情、原样重跑；一键“继续”；生成过程中发的消息排队处理；附件预览
- 🆕 **任务视图**：实时显示步骤轨迹，提供“停止”和“接管”（人接手操作后再交还给 agent）
- ✅ 悬浮球（所有机型通用的兜底入口；国产 ROM 需要额外引导开启“后台弹出界面”权限）

### F. 把关（信任）
- ✅ 工具分组开关（默认关闭，用到哪组开哪组）
- ✅ 按风险分级审批：读操作自动；写操作展示预览后审批；危险操作每次都要审批，并且要求解锁设备
- ✅ hardline 硬性禁止清单
- ✅ 无人值守时明确拒绝（返回 `tool_not_authorized`），只放行触发规则预先授权的白名单能力
- ❌ 操作日志、撤销、回收站（用户决定砍掉；删除的安全性靠审批卡片列出完整文件清单来保障）
- ✅ 用量和费用：每个任务的 token 数和费用，以及每日上限
- ✅ 工具按需加载（tool_search），工具超过 80 个时用来省 token
- ✅ Doctor 自检：权限、后台、Shizuku、无障碍、保活状态，并提供一键修复
- ✅ 密钥不写日志、不进备份；网页抓取阻断内网地址

### 明确砍掉
| 功能 | 理由 |
|---|---|
| 语音对话 | 你的判断；实际上系统输入法自带语音输入就够了 |
| 本地模型（LiteRT、AICore）和向量库 | 以 DeepSeek 为中心，本地小模型撑不起 agent |
| 多助手、多人设 | 一个 agent 就够了；不同场景交给技能来处理 |
| 子 agent 配置界面 | dsh 自己会调度子 agent |
| Telegram 机器人 | 你的判断。远程控制的需求，以后用 dsh 自身的远程能力解决更合适 |
| 内置音乐播放器 | 只需要控制，不需要自带播放 |
| Linux 工作区、SSH、编程工具链 | 写代码不是这个产品的核心 |
| 多个模型服务商的配置界面、图片生成 | 只做 DeepSeek；dsh 底层支持其他服务商，但不做界面 |
| NFC、Keystore 签名、壁纸 | 使用频率极低 |
| 内置 Web API 服务 | 会暴露端口，对外接口由 Intent 接口替代 |

## 2026-10-27 讨论结论
- 系统助手入口：保留（VoiceInteractionService + ACTION_ASSIST；国产 ROM 可能不支持，由悬浮球和磁贴兜底）
- 悬浮球：保留；与系统助手、磁贴、分享合并为一个“唤起层”模块（统一浮层面板 + 多个触发器）
- 操作日志、撤销、回收站、个人记忆：砍掉
- 内置网页服务：砍掉；工作流编辑器：用一句话建规则 + 规则列表替代
- 锁屏：工具优先走 API；每个工具标注是否需要解锁；需要解锁的步骤挂起，推送“解锁后继续”
